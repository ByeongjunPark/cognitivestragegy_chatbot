# 메타인지·AI활용 성찰 지원 시스템 (CognitiveStrategy Chatbot)

본 프로젝트는 **초중등 학습자의 메타인지 능력 신장**과 **인간-AI 간 협력적 성찰 역량 함양**을 목표로 도출된 **13대 교육공학적 설계원리**를 구현한 프로토타입입니다.

핵심 원칙: **“어디서 설정하고, 어디서 대화하고, 어디서 되짚는가”는 서로 다른 화면이어야 한다.** 다만 세션의 준비(사전지식 활성화·메타인지 점검)는 검사지 같은 폼이 아니라 **튜터와의 대화 안에서 자연스럽게** 이루어지며, 되짚기·잔여물 확인만 별도의 비대화 화면으로 분리됩니다.

Upstage **Solar Pro** 기반. 계정별로 세션이 **서버(Redis)에 누적 저장**되어, 다른 기기·브라우저에서 다시 로그인해도 지난 대화·자주 쓴 인지전략·메타인지 응답 이력이 그대로 이어집니다. (localStorage 미사용)

### 화면 흐름

| 화면 | 성격 | 하는 일 |
| :--- | :--- | :--- |
| **로그인 / 회원가입** | 비대화 | 닉네임 + **그림 4개 잠금**(슬롯 돌리기·정지 또는 직접 선택). 저연령 진입장벽 완화. 계정은 **서버 Redis**에 저장(그림비번은 pbkdf2 해시), 세션은 **HttpOnly 쿠키** |
| **내 학습터 (누적)** | 비대화 대시보드 | 지난 세션 목록 · **내가 자주 고른 인지전략**(막대) · 주도/위임 누적 비율(도넛) · 세션별 지원강도 추이 · **메타인지 점검 응답 모음** |
| **세션 시작** | 슬림 폼 | 학년군·과목·**2022 개정 교육과정 성취기준**만 선택(+선택적 목표 1줄). 나머지는 폼이 아님 |
| **대화** | 채팅 | 준비 대화(인사→목표→사전지식→이해도 1~5 인라인→메타인지 3문항)→탐구 대화. **전략 선택 칩**, 모든 AI 응답에 **수용/보류/코멘트**, 지원강도 배지(수용 누적 시 자동 옅어짐), **“나 지금 막혔어”**, 인라인 역할 조정, 자유 입력 상시 |
| **되짚기** | 비대화 대시보드 | 턴별 **내 주도/AI 위임** 태깅 타임라인 · 질문유형 도넛 · 수용 분포 · 되짚기 서술 |
| **잔여물 확인** | 비대화·AI 배제 | 지연 후 별도 세션. 근접·원거리 전이 2문항(시험지형) · 자기설명 필수 · 확신도 슬라이더 · **4축 근거**(절차적 정확도만 규칙기반, 나머지는 근거만·판정 안 함) · 전후 비교 · 델타는 학습자가 수용/보류/코멘트 · 다음 세션 시작 지원강도를 학습자가 선택 |

### 성취기준 데이터 (초3 ~ 고1)

`curriculum_standards.js` 는 **2022 개정 교육과정 성취기준 1,491건**을 담고 있으며,
[greatsong/k-curriculum-2022](https://github.com/greatsong/k-curriculum-2022) 데이터셋(교육부 고시 별책 원문, **CC BY 4.0**)에서 초3~고1 범위를 추출·정리한 것입니다.

> **학년 선택 vs 성취기준 단위**: 세션 시작 화면의 학년 드롭다운은 **초3·초4·초5·초6·중1·중2·중3·고1을 개별 선택**합니다. 다만 2022 개정 교육과정은 성취기준을 **학년군**(3~4학년군 / 5~6학년군 / 중1~3학년군 / 고1 공통)으로 고시하므로, 같은 학년군에 속한 학년(예: 초5·초6)은 동일한 성취기준 목록을 공유합니다. 개별 학년별로 분리된 공식 성취기준은 존재하지 않습니다. `index.html` 의 `bandOf(grade)` 가 선택 학년을 해당 학년군 데이터로 매핑하며, 선택한 개별 학년은 세션(`ctx.grade`)과 AI 프롬프트(`[학습자 학년]`)에 별도로 전달되어 어투·난이도 조절에 쓰입니다.
>
> 학년군별 규모: 3~4군 9과목 231건 · 5~6군 10과목 280건 · 중1~3군 14과목 714건 · 고1 9과목 266건.

## 🗄️ 백엔드 / 데이터 저장

| 데이터 | 위치 |
| :--- | :--- |
| 계정(닉네임 → `{pbkdf2 해시, salt, 생성일}`) | Redis 키 `user:<닉네임>` |
| 학습 데이터(세션·전략·메타인지·되짚기·잔여물 전체) | Redis 키 `data:<닉네임>` (JSON) |
| 세션 인증 | `sess` **HttpOnly·Secure·SameSite=Lax 쿠키** (HMAC 서명 토큰, 90일) |
| Upstage API 키 | Vercel 환경변수 `UPSTAGE_API_KEY` (브라우저 미노출) |

**API 엔드포인트**
- `POST /api/auth` — `{mode:'signup'|'login'|'logout', nickname, pin}` → `sess` 쿠키 발급/삭제
- `GET /api/data` — 쿠키 인증 후 내 학습 데이터 반환
- `PUT /api/data` (또는 `POST`, `navigator.sendBeacon`용) — 내 학습 데이터 통째로 저장
- `POST /api/chat` — Upstage Solar Pro 프록시(키는 서버에만)

**환경변수 (Vercel 프로젝트 `repo`)**
- `REDIS_URL` — Vercel Marketplace의 Redis 통합(`redis-red-magnet`, Free 30MB)이 자동 주입
- `AUTH_SECRET` — 세션 토큰 HMAC 서명 키 (48바이트 랜덤)
- `UPSTAGE_API_KEY` — Upstage 콘솔 발급 키

로컬 개발: `vercel env pull .env` 후 `vercel dev`.

## 🔑 Upstage API 키 설정 — 세 가지 중 하나

`index.html` 상단 `callLLM()` 은 아래 우선순위로 키를 찾습니다.

1. **코드에 직접 고정** — `index.html` 스크립트 최상단의 `const FIXED_API_KEY = "";` 에 키를 넣으면 프록시 없이 브라우저에서 바로 호출합니다. (공개 저장소에 올리면 노출되니, 사설/사내 배포에서만 사용하세요.)
2. **서버 환경변수 (권장, 현재 Vercel 배포 방식)** — `FIXED_API_KEY` 를 비워 두면 프론트엔드는 `/api/chat` 프록시만 부르고, 실제 키는 Vercel 프로젝트의 환경변수 `UPSTAGE_API_KEY` 에만 있습니다.
3. **브라우저 localStorage** — 정적 호스팅에서 개발자 콘솔로 `localStorage.setItem('UPSTAGE_API_KEY','up_...')` 하면 그 브라우저에서만 직접 호출합니다.

> [!WARNING]
> 과거 커밋에 테스트 키가 하드코딩되어 공개된 적이 있습니다. 그 키는 Upstage 콘솔에서 폐기·재발급하세요. 새 키를 방법 1로 넣을 경우 저장소가 공개면 노출됩니다.

### Python(Streamlit) 로컬 실행용 `.env` 설정

```env
# Upstage 개발자 콘솔 (https://console.upstage.ai/)에서 발급받은 API 키
UPSTAGE_API_KEY=여기에_발급받으신_키를_붙여넣으세요

# 모델 설정 (기본: solar-pro)
UPSTAGE_MODEL=solar-pro
UPSTAGE_BASE_URL=https://api.upstage.ai/v1
UPSTAGE_REASONING_EFFORT=medium
```
> [!IMPORTANT]
> `.env` 파일은 `.gitignore`에 등록되어 있어 git에 커밋되지 않습니다. 소스 코드를 수정할 필요 없이 `.env` 값만 입력/변경하면 됩니다.

## ▲ Vercel 배포 (API 키 안전하게 보관하기, 권장)

`index.html` + `api/chat.js`(서버리스 프록시)를 함께 배포하면, 학습자는 아무 설정 없이 바로 사용할 수 있고 API 키는 서버에만 존재합니다.

```bash
# 1. Vercel 로그인 (최초 1회, 브라우저 인증)
vercel login

# 2. 프로젝트 루트에서 배포
vercel --prod

# 3. API 키를 Vercel 환경변수로 등록 (배포와 별개로 1회 설정)
vercel env add UPSTAGE_API_KEY production
# -> 프롬프트가 뜨면 Upstage 콘솔에서 발급받은 키 값을 입력

# 4. 환경변수 반영을 위해 재배포
vercel --prod
```

배포가 끝나면 `https://<프로젝트명>.vercel.app` 형태의 URL이 발급됩니다. 이 URL이 API 키가 노출되지 않는 **정식 서비스 주소**입니다.

## 🏛️ 13대 교육공학적 설계원리 매핑 (어포던스 v1)

| 계열 | 원리 | 화면 · 어포던스 |
| :--- | :--- | :--- |
| **시스템 공통** | **1. 비계의 적응적 지원 감소(Fading)** | 지원강도(많이/보통/조금)는 **세션 시작 화면에서 한 번만** 정함. 대화 중에는 손으로 못 바꾸고, AI 응답을 “좋아요”로 2번 판단하면 **자동으로만** 한 단계 낮아지며 알림 표시(순수 적응형 페이딩). 잔여물 확인 결과가 다음 세션 시작 강도에 반영 |
| | **2. 학습자 선택권 및 최종판단 보존** | 시스템 프롬프트에 “정답·이해도·수용 여부를 AI가 단정하지 말고 판단을 학습자에게 돌려줄 것”과 “마크다운을 쓰지 말 것”을 규칙으로 고정. 전략·역할·비계·수용여부·전후 델타 판단이 모두 학습자의 클릭/입력으로만 확정. 입력창은 항상 자유 텍스트 |
| | **3. 대화과정의 기록 및 시각화** | 전 과정 **서버 Redis 저장**(계정별 누적). 되짚기 화면의 턴별 타임라인·질문유형 도넛·수용 분포 대시보드. 잔여물 확인의 4축 근거표 |
| **세션 준비 (대화 안에서)** | **4. 학습 목표 및 교과 맥락 설정** | 세션 시작 화면에서 학년군·과목·**2022 개정 성취기준**만 폼으로 선택(+선택적 목표 1줄). 대화 첫 턴에서 튜터가 성취기준을 풀어 말하고 목표를 다시 묻음 |
| | **5. 학습자-AI 간 과업 분담 명확화** | **세션 시작 화면**의 “AI가 얼마나 고쳐줄까요?” 슬라이더(힌트만 ↔ 첨삭까지)로 대화 시작 전에 학습자가 직접 설정. 원리1과 마찬가지로 대화 중에는 고정 |
| | **6. 교과 내용지식 사전 활성화 및 점검** | 준비 대화에서 튜터가 사전지식·경험을 묻고, 학습자가 답한 뒤 **1~5 이해도 칩**을 인라인으로 눌러 자가 점검 |
| | **7. 메타인지적 지식 점검** | 준비 대화에서 이해질문·전략질문·연결질문(Kramarski & Mevarech)을 한 덩어리로 자연스럽게 물음. 답변은 계정에 누적되어 **내 학습터**의 “메타인지 응답 모음”에 쌓임 |
| **대화 (인지전략 조절, 순환 절차)** | **8. 인지 전략 계획 수립** | 전략 선택 칩(생각말하기/예시로알기/따져보기/정리하기/이유찾기)을 고른 직후 **“그 방법을 고른 이유가 뭐야?”**를 반드시 묻고 답을 받아(`strategyReason`) 이후 모든 대화의 시스템 프롬프트에 근거로 실음. 탐구 대화는 화면 상단 **순환 절차 바**(①발문→②방법대로 해보기→③점검 질문→④판단, 반복)를 따라가며, 실제 프롬프트도 이 3단계를 순서대로 돌려 방법이 매 턴 반영되게 함 |
| | **9. 학습 과정 모니터링 기반 조정** | 위 순환의 “③ 점검 질문” 단계 + 입력창 옆 **“막혔어요”** 버튼 → AI가 점검 질문 1개 + 대안 전략 1~2개 제안, 최종 전략 변경은 학습자가 칩으로 선택 |
| | **10. AI 기반 응답 검증 및 수용 여부 판단** | 모든 AI 응답 아래 **판단하기** 단일 버튼(예전엔 좋아요/잘 모르겠어요/다른 생각 3개가 나란히 있었음) → 누르면 팝업에서 좋아요/잘 모르겠어요/다른 생각 중 하나를 고르고, 다른 생각이면 코멘트 입력. 버튼 자체가 지금 판단 상태를 표시. 수용 이력이 원리 1 자동 페이딩의 근거 |
| | **8·6번 연계: 공부 방법별 구조화 산출물** | 줄글로 담기 힘든 결과는 실제 표·마인드맵·비교·사슬 UI로 산출: 정리하기→표/마인드맵, 따져보기→비교, 이유찾기→인과 사슬, 예시로알기→표. AI가 순수 JSON만 반환하고 프론트가 렌더링(마크다운 미사용) |
| **직후 성찰 (대화 이후)** | **11. 학습자-AI 간 역할 및 위임 성찰** | 되짚기 화면의 가로 타임라인 — 각 턴을 눌러 **내 주도 / AI 위임** 태깅 + 주도/위임 비율 도넛 |
| | **12. 상호작용 및 질문 궤적 성찰** | 같은 화면의 질문유형 대시보드 + “다음엔 프롬프트를 어떻게 바꿀까” 서술 입력란 |
| | **13. 교과 지식 및 인지 전략 변화 성찰** | **잔여물 확인** 화면(지연 트리거, AI 배제). 구조 동일·소재만 바꾼 근접전이 + 다른 맥락의 원거리전이 2문항을 스스로 풀고 자기설명(필수)·확신도 제출 → 절차적 정확도(규칙기반)·자기설명 품질·전략 전이·메타인지 정확도 **4축 근거**를 제시하되 “향상 여부” 라벨은 붙이지 않고 학습자가 수용/보류/코멘트로 판단 |

### 이번 개정(v3)에서 바뀐 점
- **로그인/회원가입 우선** — 그림 4개 잠금으로 계정을 만들고, 이후 모든 세션이 그 계정에 누적됨
- **빠찡꼬는 그림** — 숫자가 아니라 과일·동물·사물 이모지 릴
- **성취기준 실데이터** — 2022 개정 교육과정 초3~고1 성취기준 1,491건 (greatsong/k-curriculum-2022, CC BY 4.0)
- **누적 대시보드(내 학습터)** — 자주 쓴 인지전략, 주도/위임 비율, 지원강도 추이, 메타인지 응답 모음, 지난 세션
- **검사지 느낌 완화** — 5단계 마법사를 없애고 준비(사전지식·메타인지)를 대화 안으로 이동. 폼은 “성취기준 고르기” 한 화면뿐
- **API 키** — `FIXED_API_KEY` 상수로 코드에 직접 고정 가능(+기존 프록시·localStorage 경로 유지)

### v4에서 바뀐 점
- **실제 백엔드 도입** — 학습 데이터 저장을 `localStorage`에서 **서버 Redis**로 전면 이관. 이제 기기·브라우저가 달라도 같은 계정으로 이어짐
- **서버 인증** — 그림 비밀번호를 서버에서 **pbkdf2로 해시**해 저장(평문 보관 안 함), 로그인 상태는 **HttpOnly 쿠키** (XSS 토큰 탈취 방지)
- `api/auth.js` · `api/data.js` · `api/_store.js`(node-redis) 추가

### v5에서 바뀐 점
- **AI 응답 판단을 버튼 3개 → 1개로** — 말풍선마다 다닥다닥 붙어있던 “좋아요/잘 모르겠어요/다른 생각”을 **판단하기** 단일 버튼으로 통합. 누르면 팝업에서 판단(+다른 생각이면 코멘트)을 남기고, 버튼 자체가 현재 판단 상태를 표시
- **AI 도움 정도는 대화 시작 전에만 설정** — 세션 시작 화면에서 처음 지원강도(많이/보통/조금)와 역할분담(힌트~첨삭)을 한 번 정하면, 대화 중에는 더 이상 손으로 바꿀 수 없고 **“좋아요” 판단이 2번 쌓일 때만 자동으로 한 단계씩 소거**됨(원리1 순수 적응형 페이딩)
- **마크다운 금지** — 시스템 프롬프트에 서식 규칙을 명시하고, 혹시 새어 나온 `**굵게**`나 `#제목`, 목록 기호 등은 `stripMarkdown()`이 방어적으로 한 번 더 제거
- **상단 진행 단계 바** — 화면 최상단에 `① 대화 시작 전 → ② 대화 중 → ③ 대화 이후` 3단계 진행 상황을 항상 표시
- **탐구 대화의 순환 절차를 시각화 + 실제로 구현** — 대화 중에는 진행 단계 바 아래에 `① AI가 발문 → ② 방법대로 해봐요 → ③ 점검 질문 받아요 → ④ 내가 판단해요 → (반복)` 루프를 보여주고, 실제 시스템 프롬프트도 이 3단계(발문/전략적용/점검)를 순서대로 돌며 생성함 — 예전처럼 전략과 무관하게 매번 같은 톤의 발문만 반복하지 않음
- **인지 전략 선택을 더 구체적으로** — 방법을 고른 직후 “왜 그 방법을 골랐어?”를 반드시 물어 그 이유(`strategyReason`)를 받고, 이후 모든 대화의 시스템 프롬프트에 함께 실어 방법이 실제로 그 이유에 맞게 적용되도록 함
- **공부 방법별 구조화 산출물** — 줄글로 표현하기 어려운 결과를 실제 어포던스로 산출: 정리하기→**표/마인드맵**, 따져보기→**비교(내 생각 vs 반박)**, 이유 찾기→**원인→결과 사슬**, 예시로 알기→**예시 표**. 대화창의 “빠른 버튼”을 누르면 AI가 순수 JSON으로만 응답하고 프론트가 실제 HTML 표·마인드맵·비교표·사슬 다이어그램으로 렌더링(마크다운 문법을 전혀 쓰지 않음)

## 🚀 실행 방법

### 방법 1: 원클릭 배치 파일 실행 (가장 추천)
프로젝트 폴더 내의 **`run_chatbot.bat`** 파일을 더블 클릭하면 자동으로 환경을 감지하여 웹 브라우저가 실행됩니다.

```bash
# 1. 의존성 패키지 설치
pip install -r requirements.txt

# 2. 스트림릿 애플리케이션 실행
streamlit run app.py
```

실행 후 웹 브라우저에서 `http://localhost:8501`로 접속됩니다.
