## 방법
- **실행기**: `tools/student-agent/pilot.mjs`. 로컬 서버(`?local`)를 띄우고 Chrome(헤드리스)으로 앱 전체를 끝까지 사용한다. 순서는 가입 → 둘러보기 → 시작 → 아는 것 확인 → 스스로 점검 → 방법 → 탐구 → 돌아보기 → 혼자 풀어보기 → 저장이다.
- **학생 페르소나 4종 × 시나리오 4종 = 16회**
  - 페르소나: 보통형, 이해 부족형, 초3 저학년형(짧고 모호한 답), 딴짓형(답 요구·잡담·장난)
  - 시나리오: 초5 분수의 덧셈, 초6 4·19와 6월 민주 항쟁, 초6 과학 남중 고도(`science_namjung`), 중1 일차방정식 단계 풀이(`math_equation`)
- **결함 주입 모의 LLM**: `tools/student-agent/mock-llm.mjs`. 이 PC에 Upstage 키가 없어 실제 Solar 대신 쓴다. 평가·관찰에서 나온 결함 10종을 응답의 35%에 섞는다. 반말, "왜 그렇게 말했어?", 위젯 없는 "아래에서 골라", "알고 배는 거야" 비문, 7문장 장문, 질문 2개, 마크다운 목록, 남중 고도 '커요', 영어 낱말, 지시문 유출이 그 결함이다. 재생성 요청에는 60%만 고쳐 답한다. 스트레스 시험은 결함 60%·고침 20%로 돌렸다.
- **비교**: 같은 학생·같은 모의 LLM·같은 난수 씨앗으로 개선 전 원본(`d6459e0`, git worktree)도 돌렸다. 지표는 개선 후 라이브러리(`js/lib/*`) 한 가지 잣대로 학생 화면에 실제로 나간 문장을 잰다.
- **사람 기준 소요시간 추정**: 학생이 읽은 화면 글자 수(÷분당 읽기: 초3 150·초5~6 220~250자), 친 글자 수(÷분당 타자: 초3 12·초5~6 22~25자), 누른 횟수(×3초)를 더했다. 에이전트의 실제 실행 시간(회당 약 11초)과 AI 응답 지연은 빼고 사람의 조작 시간으로 바꿔 계산한 것이다.

## 한계(꼭 함께 읽기)
1. **모의 LLM**: 이 지표는 "결함이 섞인 모델 출력을 코드가 학생 화면에 닿기 전에 걸러 내는가"를 잰다. 실제 Solar의 결함 빈도, 대화 맥락 적합성, 교과 정확성 자체는 재지 않는다. 키가 있으면 `run.mjs --url <배포주소>`(실제 모델)로 같은 지표를 다시 재야 한다.
2. **인정·공감 포함률**은 모의 LLM이 늘 인정 문장을 넣으므로 이번 시험에서는 변별력이 없다(전후 모두 100%). 실제 모델로 다시 재야 한다.
3. **소요시간**은 읽기·타자 속도 가정에 기댄 추정이다. 실제 수업의 사고 시간과 교사 안내 시간은 빠져 있다. 배포 뒤 `phaseTimes` 학급 중앙값(교사 화면 2-1)으로 보정한다.
4. **"반말 섞임" 지표**는 개선 전 설계가 의도한 반말 AI 문장도 센다. 개선 전 문제는 반말 AI와 해요체 안내문이 섞인 것이었으므로 혼재의 대리 지표로 썼다.
