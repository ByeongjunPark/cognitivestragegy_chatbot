## WP0-2 재현 4건

### 1) 역할분담 슬라이더 방향 (전문가4·2) — **재현됨**
- 절차: 시작 화면에서 [AI와 할 일 나누기 · 바꾸기]를 펼치고 "문제가 뭔지 명확히 정하기" 막대를 오른쪽 끝(100)으로 민다.
- 개선 전: 막대 양끝 라벨은 **왼쪽 "AI가 맡아요" / 오른쪽 "내가 맡아요"**였고, aria-label도 "0은 AI가, 100은 내가"였다. 그런데 막대 위 라벨 `tbSliderLabel(100)`, 요약 `renderTaskBrief`, 시스템 프롬프트 `sysPrompt().aiTasks`(index.html 2684·2695·4316행)는 **값 ≥ 50이면 AI**로 읽는다. 오른쪽 끝으로 밀면 끝 라벨은 "내가 맡아요"인데 막대 위 라벨과 요약과 AI 지시는 모두 "AI가 많이"였다.
- 원인: 화면 끝 라벨만 반대로 쓰여 있었다. 데이터 의미(≥50 = AI)는 최근 5회 평균 기능과 묶여 있어 그대로 두고, 라벨을 고쳤다(WP1-1).
- 회귀 테스트: `tests/scoring.test.mjs` "값 → 라벨 → 요약 → aiTasks 세 경로" 테스트.

### 2) 스스로 점검 33점 vs 88점 (전문가6) — **재현됨(원인 확정)**
- 절차: 사전 문항 4개를 대부분 맞힌다(예: 100·100·50·100 → 평균 88). 자신감을 고르고, 스스로 점검에서 짧게 답한다. 하위 지표가 1개씩만 충족되면 각 축이 33점이 된다.
- 개선 전 화면: 같은 "스스로 점검 결과" 카드 안에 `이해 33점 · 전략 33점 · 연결 33점`이 보이고, 바로 아래 보정도 문장이 **"실제 확인 결과(88)"**라고 쓴다(3384행 `calibSentence`). 이 88은 **사전 확인 문제** 평균이다. 다른 척도가 같은 카드에서 같은 숫자 꼴로 섞여 보였다.
- 채점 엄격성: `gradeMeta` 프롬프트에 "애매하면 0"이 있었고, 점수는 0/33/67/100 네 값만 나온다.
- 시범 운용 계측: 개선 전 코드에서는 16회 중 13회(81%)에서 이 혼재가 나타났고, 개선 후에는 0회다(`docs/pilot-report.md`).

| 같은 세션의 화면 | 개선 전 표시 | 개선 후 표시 |
|---|---|---|
| 스스로 점검 카드 | 이해 33점·전략 33점·연결 33점 + "실제 확인 결과(88)" | 3단계 막대("해 보는 중이에요") + 하위 지표 체크. 사전 확인 점수는 이 카드에 없음 |
| 방법 고르기 요약(levelSummary) | "아는 것 88점 · 스스로 점검 33점" | "사전 확인 문제 88점"(파랑) / "스스로 점검: 해 보는 중이에요"(초록), 보정도는 따로 "사전 확인 문제" 이름으로 |
| 내 공부방 스스로 점검 탭 | 숫자 막대 33점 | 3단계 이름(그래프 축도 이름) |
| 교사 CSV | meta_understand 33 | meta_understand 33 + meta_level_understand 1 (같은 `CS.metaScoreView`) |

### 3) "아래에서 골라줘"인데 선택지 없음 (전문가6) — **경로 확인**
코드로 확인한 경로는 두 가지다.
- (가) LLM이 자유 발화에서 "아래에서 골라"를 말해도, 그 턴에 위젯을 붙이는 장치가 없었다. 인사 턴("문항이 곧 카드로 뜰 거야" 지시를 받은 모델), 막혔어요 턴, 자신감 재안내 턴(`ai(..., 'prior-pick')`은 LLM 문장 그대로)이 여기에 해당한다.
- (나) `ai()`가 실패하면 `pushAi(err.message)`가 kind 없이 들어가, `priorscore` 단계에서 고를 위젯이 없는 채로 남는다.
- 시범 운용 계측(같은 결함 주입): 개선 전 회당 0.75건, 개선 후 0건.

### 4) 돌아보기에서 자동 생성 문장이 학생 발화로 분류 (전문가4) — **재현됨**
- 개선 전: "질문 돌아보기(나)" 목록은 `AUTO_ME_RE`로 걸렀지만, **"누가 이끌었나(가)" 타임라인은 모든 `me` 턴에 [내가 생각]/[AI에게 맡김] 표시 버튼을 붙였다**. 그래서 "(표로 정리하기)", "지금 막혔어…", "… 방법으로 해볼게." 같은 버튼 문장도 학생 발화로 표시 대상이 됐다.
- 시범 운용 계측: 개선 전 회당 2.0건, 개선 후 0건.

| 도움 종류 칩(help-pick) | "작은 힌트가 필요해요." 등 | `button` |
| 까닭 칩(reason/change-reason) | "오늘 내용에 잘 맞아 보여서" 등 | `button` |

- 되짚기 타임라인 표시 버튼, 질문 목록, 내 공부방 "내가 보낸 말", 질문 궤적, 성찰 질문 받기는 모두 `isTyped()`(= `src==='typed'`)만 쓴다.
- 구버전 세션(`src` 없음)은 불러올 때 `migrateAccountData()`가 예전 규칙(`AUTO_ME_RE`)으로 한 번 `src`를 채운다. 새 필드만 추가하고 기존 필드는 바꾸지 않는다.
